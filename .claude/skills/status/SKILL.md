# STATUS.md の更新

`STATUS.md` は今井泰介先生にそのまま送れる状態を常に保つための文書である。

## 手順

1. `STATUS.md` を読む。
2. 前回更新以降の変化を確認する。`log.md` があれば最新のエントリ、なければ `derived/` の更新日時と `docs/specs/` の改訂履歴から確認する。
3. 下記のルールに従って `STATUS.md` を書き換える。数字は `derived/` の実データで確かめてから書く。
4. 冒頭の日付を今日にする。
5. 変更点を1〜3行で私に報告する。

## 文体

- 手紙として書く。宛名から始め「よろしくお願いいたします」で終える。です・ます調の地の文。
- 先生はこちらの作業の中身や用語を知らない前提で書く。
  - 内部の呼び名（「S-all」「Step 3」「名寄せ」「model2vec」など）をそのまま出さず、何をする作業かを言葉で説明する。
  - 固有名詞は初出時に一言添える。例:「SciBERT（科学論文で学習された言語モデル）」
- 数字は文章の中に置く。表は原則使わない。どうしても必要な場合は1つまで。
- 手法を変えた場合は、元の案が駄目だった理由を具体例とともに書く。
- 見出しは内容を表す日本語にする。

## 何を書くか

- 何を目指している課題なのか（毎回冒頭に置く）
- これまでにできたこと
- 分かったこと。特に当初の想定と違っていた点
- いま止まっていること。解決の見通しがあるかどうか
- ご判断をお願いしたいこと。背景・選択肢・こちらの推奨と理由をセットで書く
- 今後の予定

## 何を書かないか

- 経緯・試行錯誤・失敗と修正の過程（`log.md` に書く）
- 実装の詳細（スクリプトの内部設計、ファイル名）。詳細は文書へのパス参照だけにする
- 「〜と思われる」で濁す書き方。確認できた事実か、未確認かを明示する

A4で2〜3ページ程度。
